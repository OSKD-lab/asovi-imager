# ASoVi Imager ユーザーガイド

![ASoVi Imager](imgs/fig1.png)

このガイドは、**プログラミングをほとんどやったことがない方**が、ASoVi Imager
（広視野皮質イメージング＝WFCI の解析ソフト）を自分のパソコンで動かせるように
なることを目標にしたドキュメントです．

順番どおりに進めれば、最後には

- ソフトを起動して
- 自分の撮影データ（またはサンプルデータ）を読み込み
- 解析を実行して
- 結果ファイルを取り出す

ところまでできるようになります．

> **IMPORTANT**：うまくいかないときは、あわてず [第9章 困ったとき](#第9章-困ったとき) を
> 見てください．

## はじめに：このソフトは何をするもの？

マウスなどの脳を上から広く撮影した動画（WFCI）から、

1. **ゆれ補正**（撮影中の微妙なズレを直す）
2. **明るさ変化の抽出**（dF/F：脳活動に対応した信号）
3. **ノイズ除去**（PCA / ICA という手法）
4. **脳地図へのあてはめ**（Allen アトラスという標準脳への位置合わせ）
5. **領域ごとの信号の取り出しと相関の計算**
6. **書き出し**（動画・画像・数値ファイル）

を自動で行うツールです．もともと MATLAB で作られていたものを Python に移植した
ものです．**難しい中身は知らなくても、画面（GUI）のボタンを順に押すだけで**
使えるように作られています．

## 第0章 準備：`uv` を入れる

最初にやることは、**`uv` という道具を1つ入れるだけ**です．Python やその他の
部品は、あとで `uv` が全部自動でそろえてくれます．

### 0-1. ターミナルを開く

**Windows の場合**

1. 画面下の「スタート」ボタン（Windows マーク）を押す
2. `powershell` と入力する
3. 出てきた **「Windows PowerShell」** をクリックして開く

**Mac の場合**

1. `command（⌘）+ space` で Spotlight 検索を開く
2. `terminal` と入力する
3. 出てきた **「ターミナル」** をクリックして開く

黒い（Mac は白いことが多い）画面が出たら成功です．ここに文字を打ち込んでいきます．

### 0-2. `uv` をインストールする

下のコマンドを**まるごとコピーして、ターミナルに貼り付けて Enter**を押します．
（ターミナルへの貼り付けは、Windows は右クリックまたは `Ctrl+V`、Mac は `⌘+V`）

**Windows（PowerShell に貼り付け）**

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**Mac（ターミナルに貼り付け）**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

しばらく文字が流れて、`installed` のような表示が出れば完了です．

> **別の入れ方（お好みで）**
> - Windows で「winget」が使える人：`winget install --id=astral-sh.uv -e`
> - Mac で「Homebrew」を使っている人：`brew install uv`

### 0-3. インストールできたか確認する

**いったんターミナルを閉じて、開き直してください．**（`uv` の場所をパソコンに
覚えてもらうために必要です．）

開き直したら、次を打って Enter：

```bash
uv --version
```

`uv 0.x.x` のようにバージョンが表示されれば **成功** です 🎉
（数字は違っていて大丈夫です．）

表示されない・エラーになる場合は [第9章](#uv-が見つからないと言われる) を見てください．

## 第1章 プログラム本体を入手する

次に、ソフトの中身（プログラム一式）をパソコンに置きます．方法は2つ．
**どちらか片方**でOKです．

> ⚠️ 研究室の非公開リポジトリの場合、入手にはアクセス権（GitHub へのログインや
> 招待）が必要なことがあります．うまくいかないときは、共有してくれた方に
> 「入手方法」を確認してください．

### 方法A：ZIP でダウンロードする（いちばん簡単）

1. 配布元（GitHub など）のページを開く
2. 緑色の **「Code」** ボタン →**「Download ZIP」** をクリック
3. ダウンロードした ZIP を **右クリック →「すべて展開」**（Mac はダブルクリック）
4. 出てきたフォルダを、分かりやすい場所（例：Windows なら `C:\work\`、Mac なら
   `書類` フォルダ）に置く

> 展開後のフォルダの中に **`pyproject.toml`** というファイルと **`src`**
> というフォルダが見えていれば正解です．この「いちばん外側のフォルダ」を、
> このガイドでは **プロジェクトフォルダ** と呼びます．

### 方法B：`git` で入手する（あとで更新が楽）

`git`（ギット）という道具を使う方法です．将来アップデートを受け取りたいなら
こちらが便利ですが、初めてなら方法Aで十分です．

`git` が入っていれば、ターミナルで次のように打ちます（`<URL>` は配布元の
アドレスに置き換えてください）：

```bash
git clone <URL>
```

## 第2章 初回セットアップ（`uv sync`）

ここで、ソフトが動くのに必要な部品（Python 本体を含む）を**一括でそろえます**．
1回だけやればOKです．

### 2-1. プロジェクトフォルダへ「移動」する

ターミナルは今どこかのフォルダに「いる」状態です．これを、第1章で用意した
**プロジェクトフォルダ**（`pyproject.toml` があるフォルダ）に移動させます．

移動には `cd`（チェンジ・ディレクトリ）というコマンドを使います．**いちばん
簡単なコツ**は、`cd ` と打った後（`cd` のあとに半角スペースを1つ）、

- **フォルダをターミナルの画面にドラッグ＆ドロップ**する

方法です．すると自動でフォルダの場所（パス）が入るので、そのまま Enter．

```text
cd （ここにフォルダをドラッグ＆ドロップ）→ Enter
```

うまくいくと、ターミナルの行頭にフォルダ名が表示されます．

> 手で打つ場合の例：
> - Windows：`cd C:\work\ASoVi_imager`
> - Mac：`cd ~/Documents/ASoVi_imager`

### 2-2. 部品をそろえる

移動できたら、次のコマンドを打って Enter：

```bash
uv sync
```

これで、Python 3.13 とこのソフトに必要なライブラリが自動でダウンロード・
インストールされます．

> ⏳ **初回はとても時間がかかります**（回線にもよりますが数分〜十数分）．
> `torch` など大きな部品を含むため、**数 GB のダウンロード**と保存が発生します．
> 途中で止まったように見えても、ネットにつながっていれば待てば進みます．

`uv sync` が終わってターミナルの入力待ちに戻れば、準備は完了です．

### 2-3. あとで更新するとき

`git` で入手した（方法B）なら、新しい版を取ってきて入れ直します：

```bash
git pull
uv sync
```

ZIP（方法A）なら、新しい ZIP を落としてこの章をやり直します．設定と結果は
データのそばに置かれ、プロジェクトフォルダの中には入らないので、更新しても残ります．

## 第3章 ソフト（GUI）を起動する

いよいよ本体を起動します．**プロジェクトフォルダにいる状態**（第2章の続き）で、
次を打って Enter：

```bash
uv run python -m asvimg.gui
```

しばらくすると、**「ASoVi Imager - Pipeline」** という操作画面（GUI）が開きます．

> 💡 `uv run` は「このプロジェクト用の環境で動かす」という意味です．毎回この形で
> 起動します．
>
> 📌 `uv run asovi-gui` と打っても同じものが起動します．`uv sync` がプロジェクト自体を
> インストールするので、`asovi-*` のコマンドはこの環境の中にあります．**`uv run` は
> 付けたままにしてください** — 名前だけでは PATH に無いので動きません．

**閉じるとき**は、ウィンドウの×ボタンで閉じてOKです．ターミナルは開いたままで
かまいません（次の起動にまた使います）．

## 第4章 解析するデータを用意する

### 対応しているファイル形式

このソフトは次の撮影ファイルを読み込めます：

- `.tif` / `.tiff`（OME-TIFF を含む）
- `.dcimg`（浜松ホトニクス）
- `.sifx`（Andor のスプールフォルダ）
- `.nd2`（Nikon NIS-Elements）
- 偶数／奇数に分けて保存された `.h5` 録画フォルダ（伊藤研形式）

> 📌 **`.nd2` を使うとき**：1 つの時刻の中に全チャンネルが入っているので、
> `channels_name` には **ND2 に保存されている順番どおり**に色を並べてください
> （個数が ND2 のチャンネル数の倍数でないと前処理が止まります）．`fps` は
> 「全チャンネル合わせて1秒あたり何枚か」です．Z スタックや多点（P）撮影の
> ファイルは読めません．

### 置き方のルール

**1回の録画に関するファイルを、1つのフォルダにまとめて置きます．** そのフォルダ
（＝ **入力フォルダ / Input dir**）を、あとで画面で指定します．

1つのフォルダに**違う形式が混ざっている**と、前処理は推測せずに止まります．
その場合は Data の **`input_format`** でどちらを読むか明示してください．

### まずは小さなデータで練習

> ⚠️ **`Analysis/_sampleData01` などのサンプルデータは、配布物には入っていません．**
> （実験データはサイズが大きいため、プログラム本体とは別に管理されています．）
> 練習用データが必要なときは、プログラムを共有してくれた方に別途もらってください．

自分のデータで試すときは、**録画時間の短いもの**を1つ選んで入力フォルダに指定するのが
おすすめです．長い録画しかない場合は、**Preprocess › General** の **`max_frames`** に
`500` などを入れると、先頭 500 フレームだけで最後まで通して動作確認できます．

## 第5章 実際に解析してみる

### 5-1. 画面のみかた
![GUI-summary](imgs/fig2.png)
GUI は大きく **4つ+α** に分かれています（画像の番号に対応）．

**1： 設定（Configuration）** … 解析の各種パラメータを入れる場所．
項目は「Data / Channels / Preprocess / …」とグループに分かれています．

- Presets: よく使う設定や以前のを読み込む
- Data: 入力フォルダや出力形式など (db.yaml に対応)．セクションの一番下に2つのボタンがあります
  - **Make export dir**：出力フォルダ（`output_dir`．空欄なら `<input_dir>/asi/<形式>`）を先に作り、そこへ `db.yaml` / `ops.yaml` を書き出します（解析を走らせる前に設定だけ保存しておきたいとき）
  - **sifx converter**：Andor の `.sifx` スプールが入ったフォルダを選ぶと、全フレームを1本の BigTIFF にまとめます
- Channels: 撮影の色（チャンネル）の並びやプローブ名など．フレーム毎に励起光/Probe の切り替えがある構造を想定
- Preprocess: ゆれ補正や dF/F 計算のパラメータ．一番下の **5. TIFF output** にある
  チャンネルごとの TIFF 書き出し（`save_raw_each_ch` / `save_registered_each_ch` と
  `tiff_format` / `tiff_compression`）は **Outputs にも同じものが出ます**．どちらで
  変えても連動し、書き出すのは preprocess です
- PCA / ICA: 主成分・独立成分の数や除外の設定 (デノイズ，Allen CCF へのマッピングに使用)
- Annotation: 脳地図合わせの設定 (アトラスの種類やランドマークの指定)
- ROI: 信号読み出し用 ROI と領域間相関の設定（Stages の **Edit ROIs** でカスタム ROI を作成可能）
- Outputs: **何をファイルに書き出すか**の ON/OFF．**Frames / Movie / ROI / Figures / Configs** の小見出しに分かれています．動画 (`save_movie`)、確認用の図の保存 (`save_figures`)、脳地図に合わせた dF/F (`save_annotated_dF_mat`)、ROI 信号の CSV (`save_roi_signals`) はすべてここにあります

**2： 解析ステージ（Stages）** … 解析の進行状況を管理する場所．

- **Run All / Stop**：7ステージ（下の 5-4）をまとめて実行 / 中断するボタン
- **Quick Preview**：**最初のファイル**の先頭数フレームを確認表示（5-3 参照）
- **Quick Preview (All)**：**すべてのファイル**の先頭フレームを 1 ファイル 1 行で表示（5-3 参照）
- ステージ一覧：各ステージの **State**（状態）・**Last run**（最後に終わった日時）・**Show**（前回保存した図をディスクから読み直して表示．**再実行はしません**）・**Run**（そのステージだけ実行）
- **Utilities**（ステージ表の下の一列）
  - **Open input folder** / **Open output folder**：入力／出力フォルダをエクスプローラ（Finder）で開く
  - **Edit ROIs**：ROI エディタを起動してカスタム ROI を作成し `rois.csv` に保存（**annotation が終わるまで灰色で押せません**）
  - **Seed-based Corr. Maps**：ある ROI を「種（seed）」にして脳全体との相関マップを計算・表示（`asi/.../corrMap/` に保存）．**「Add for Annot.」** を押すと、そのマップを元画像の座標に戻して `map_for_annot/` に置き、cpselect の背景に使えます（**`marks.mat` が必要**＝ annotation を先に）
  - **Preview Movie**：書き出し済み動画を 5 のウィンドウで再生（**export が動画を書き出すまで灰色で押せません**）

**3： Figures** … 解析中に出力される確認用の図を一覧表示する場所．

- PCA/ICA のスペクトル・空間マップ、annotation の位置合わせ結果、ROI 信号、相関行列など、ステージごとの図がまとまって出てきます
- 各項目をクリックすると展開して画像を確認できます

**4： Log** … 処理の進み具合やメッセージが流れる場所．

- 各ステージの処理内容（保存したファイル名、フレーム数など）が逐次表示されます
- **エラーもここに出ます**．`Error`（赤）が出たときはまずここを確認してください

**5： Movie Preview（+α）** … 動画出力完了後に **「Preview Movie」** ボタンから表示されるポップアップ．

- 書き出した動画（チャンネル名ごとに1本）を横に並べて**同時に再生**する
- **「> Play」** で再生・一時停止．下のスライダーでコマ送り（頭出し）ができます
- 再生速度は **x0.25 / x0.5 / x1 / x2 / x4** から選べます
- **`x1` = 実時間**（1チャンネルあたりの撮影レート）です．`save_movie_speed` を上げて早回しの動画として書き出していても、このプレビューの x1 は実時間で再生されます

### 5-2. 最低限そろえる設定

初めては、次の項目だけ確認すれば動きます．ほかは初期値のままでOKです．

| 場所 | 項目 | 何を入れる？ |
| --- | --- | --- |
| Data | **input_dir** | 撮影データの入っているフォルダ．右の `...` ボタンで選べます．**初期値の `Analysis/_sampleData01` は存在しないパス**なので、必ず自分のデータのフォルダに書き換えてください． |
| Data | **output_format** | 結果の保存形式．`mat`（MATLAB用）/ `npy`（Python用）/ `h5`．迷ったら `mat`． |
| Channels | **channels_name** | 撮影の色（チャンネル）の並びをカンマ区切りで．例：`GCaMP,jRGECO`．**撮影の実際と合わせる**のが最重要． |
| Channels | **channels_prop** | 各チャンネルの役割を `source` または `donner` でカンマ区切り．分からなければ全部 `source`． |
| Channels | **ch_for_annotation** | 脳地図合わせに使うチャンネル番号（**0 から数えます**：最初のチャンネルが 0）． |
| Preprocess › General | **fps** | 撮影のフレームレート（全チャンネル合計の1秒あたり枚数）． |

> 💡 **`*` マーク**が付いた項目は「再現性に関わる大事な設定（db）」です．特に
> チャンネル設定は撮影条件そのものなので、慎重に．

### 5-3. まず「Quick Preview」で確認

右上の **「Quick Preview」** を押すと、**最初のファイル**の先頭12フレームがチャンネル名
つきで表示されます．**色（チャンネル）の並びが合っているか**をここで確認してください．
（読み込む予定のファイル名・サイズ・日時も、読み込む順番で Log に出ます．）

- **名前（ラベル）そのものが違う**（撮っていない色の名前が出ている）→ `channels_name` を直します
- **名前は合っているが、割り当てが1コマぶんずれている**（先頭のフレームが2番目の色になっている）
  → **`channels_name` の順番を入れ替えてはいけません**．順番を回すと `channels_prop`
  （`source` / `donner`）との対応まで一緒にずれて、dF/F の血流補正が壊れます．
  Channels の **`demux_start_offset`** で直してください（下記）．

撮影データが**複数ファイルに分かれている**ときは、隣の **「Quick Preview (All)」**
を押してください．**すべてのファイルの先頭**が 1 ファイル 1 行で並ぶので、
「このファイルだけ色の並びがずれている」がひと目で分かります．そういうファイルが
あったら、Channels の **`channels_slip`** に**ファイルの数だけ**数字を並べて直します．

- 例：ファイルが3つあり、2つ目だけ 1 コマぶんずれている → `0,1,0`
- 直ったかどうかは、もう一度 **Quick Preview (All)** を押して確認できます

**録画全体が丸ごとズレている**（Quick Preview で見た**先頭のフレームの色が違う**）ときは、
Channels の **`demux_start_offset`** に「先頭を何コマぶん後ろにずらすか」を入れます
（`0` から数えます．2チャンネルなら `1` で入れ替わります）．**録画全体に効く、いちばん
簡単なつまみ**です．直ったかどうかは、もう一度 **Quick Preview** を押して確認できます．

ズレの種類と直し方をまとめると：

| ズレ方 | 直す場所 |
| --- | --- |
| 録画全体が丸ごとズレている | Channels の **`demux_start_offset`** |
| **特定のファイルだけ**ズレている | Channels の **`channels_slip`**（ファイルの数だけ数字を並べる） |
| **録画の途中（ファイルの中ほど）から**入れ替わる | [第9章の Demux 補正ツール](#チャンネルの並び色が途中でズレる入れ替わる) |

#### 読み込む順番（`input_order`）

複数ファイルは**上から順につなげて 1 本の録画**として扱われます．
順番そのものは Data の **`input_order`** で選べます．

| 選択肢 | 並び方 | こんなとき |
| --- | --- | --- |
| `natural` | 名前の自然順（`rec_2` が `rec_10` より前）| **既定**．分割保存されたファイルはこれで合います．エクスプローラの表示もこれと同じです |
| `name` | 名前の辞書順（`rec_10` が `rec_2` より前）| MATLAB の `dir` や Python の `sorted()` と同じ並び．昔のスクリプトに合わせたいとき |
| `mtime` | **更新日時**の古い順 | 名前順では撮影順にならないとき．カメラが書いた時刻＝撮影時刻で、コピーしても保たれます |
| `ctime` | **作成日時**の古い順 | 下の注意を読んでから |

> ⚠️ **`ctime`（作成日時）は撮影順とは限りません．** Windows では、ファイルを別のディスクに
> コピーしたりバックアップから戻したりすると、作成日時が**コピーした時刻に付け替わります**．
> ネットワーク共有に置かれたデータでは、作成日時順はバラバラなのに更新日時順は撮影順のまま、
> ということがよくあります．**まず `mtime` を試してください．**

**実行する前に必ず「Quick Preview (All)」で確認してください．**
選んだ順番でファイルが並び、Log に**作成日時と更新日時の両方**が出ます．
並べ替えに使った列には見出しに `<-` 印がつくので
（`mtime` / `ctime` のときは各行にも、`natural` / `name` のときは並べ替えの基準が
ファイル名なので name の列に印がつきます）、
**印のついた列が思った順番に並んでいるか**を見れば、順番が正しいか分かります．
どの順番を選んでも日時は両方出るので、**別の順番のほうが良かった**かどうかもここで分かります．
図のほうも上から読み込み順に `#1`, `#2`, … と並びます．

順番を変えると次の2つも変わります．

- **先頭のファイル**が実験名のもとになります．`exp_name` を書けば `{exp_name}_*` の出力名は
  固定できますが、**`roiSignals_*` の名前は `exp_name` では変わらず**先頭ファイル由来のままなので、
  順番を変えると `roiSignals_*` の名前も変わります
- **`channels_slip`** は「読み込み順で何番目のファイル」を指すので、順番を変えると対応もずれます

### 5-4. 解析を走らせる

解析は次の順番の **7ステージ** で進みます：

```text
preprocess → pca → ica → annotation → roi → correlation → export
（前処理）  （主成分）（独立成分）（脳地図合わせ）（領域信号）（相関）（書き出し）
```

やり方は2通り：

- **まとめて実行**：右上の **「Run All」** を押すと、上から最後まで自動で進みます．
- **1段ずつ実行**：各ステージ行の **「Run」** を押すと、その段だけ実行します．
  （各ステージは、必要なデータをディスクから読み直すので、単独でも動きます．）

各ステージの状態は次の表示で分かります：

| 表示 | 意味 |
| --- | --- |
| `Pending`（灰） | まだ実行していない |
| `Running`（黄） | 実行中 |
| `Done`（緑） | 完了 |
| `Done (* param-changed)`（オレンジ） | 完了しているが、**そのあと設定を変えた**ので、いまディスクにある結果は今の設定と一致しません．もう一度 **Run** で作り直されます |
| `Skipped`（灰） | 実行しなかった．例：`skip_ica` がオン／脳地図合わせを `False`・Cancel した（＝ ROI・相関・書き出しも走りません）／**Stop で中断した preprocess**（出力が録画の“途中まで”なので、完了＝Done にはしません．必ずやり直してください） |
| `Error`（赤） | エラー（Log を確認） |

**Last run** の列には、そのステージが**最後に終わった日時**が出ます（そのセッションで
実行した場合は、かかった秒数も括弧で付きます）．

> 初めては **「Run All」** で最後まで通してみるのがおすすめです．途中で止めたい
> ときは **「Stop」** を押します．

### 5-5. 脳地図合わせ（annotation）の操作

`annotation` は**初期値が `cache`** です．この状態で `annotation` を実行すると、
**`marks.mat` がまだ無いとき（＝初回）だけ**、脳地図合わせ用の別ウィンドウ（cpselect）が
自動的に開きます．ここでは、**自分の脳画像と標準脳（アトラス）で対応する点**をクリック
して指定します．

- **「+ Add Pair」** で点のペアを追加、**「Delete Selected」** で選んだペアを削除します
- 目印（ランドマーク）のボタン、**「Show Borders」**（境界線の表示切り替え）も使えます
- 左の画像は **「<」「>」** ボタンで切り替えられます（平均画像のほか、計算済みの
  **PCA / ICA の成分マップ**、`map_for_annot/` に置いた画像）．血管ではなく機能的な境目を
  見ながら合わせたいときに便利です
- 指定できたら **「Finish」** で確定します．**「Cancel」** で閉じると `marks.mat` は
  保存されず、annotation は `Skipped` になり、**ROI・相関・書き出しは実行されません**

決めた対応点は `marks.mat` に保存され、**2回目からは自動で再利用されてウィンドウは
開きません**（設定を変える必要はありません）．**打ち直したい**ときだけ `annotation` を
**`gui`**（毎回必ず開く）にします．

**脳地図合わせをしない**なら `annotation` を **`False`** にします．このとき
annotation は `Skipped` になり、脳地図に依存する **ROI・相関・書き出しも自動でスキップ**
されます（前処理と PCA / ICA だけを回したいときに使えます）．

> 💡 **脳地図合わせをせずに ROI 信号だけ取りたい**ときは、`roi_space` を **`source`** に
> して、**録画画像そのものの座標**で ROI を書いた `rois_source.csv`（列は `name,x,y,size`。
> reg/dff のビニング後のピクセル座標）を出力フォルダに置きます．このファイルを作る
> エディタはありません（自分で書きます）．無ければ ROI ステージは何も出しません
> （生の録画には既定 ROI が無いため）．既定の `atlas` は脳地図合わせが必要です．
>
> ⚠️ **ただし Run All では走りません．** Run All は annotation が transform を作らなかった
> 場合、`roi_space` に関係なく ROI・相関・書き出しを飛ばします．`roi` の行と `correlation`
> の行の **Run** を 1 つずつ押してください（書き出しは脳地図合わせが必要なままです）．

### 5-6. ノイズ成分の選択（ICA）

`ica_exclusion` は**初期値が `cache`** です．この状態で `ica` を実行すると、**まだ選択を
記録していないチャンネル（プローブ）についてだけ、自動的に**成分（IC）の一覧が並んだ
ウィンドウが開きます．ノイズだと思う成分を**クリックして除外**（赤い枠が付いたら除外対象）
し、**「Apply」** で確定します．よく分からないうちは、明らかに変な（画面の端や血管だけが
光る、呼吸に合わせて明滅するような）成分だけを外し、あとはそのまま Apply でも構いません．

- **「Cancel」** は「選ばなかった」扱いで、前の記録がそのまま残ります（「除外なし」とは
  別物です）．全部の選択を外したいときは **「Clear all」** を押してから Apply します
- 成分の分解は**チャンネル名（プローブ）ごとに別々**に行われます．たとえば GCaMP と
  jRGECO を撮っていれば **ウィンドウが 2 回開きます**（タイトルに
  `ICA - GCaMP (1/2) - Click to EXCLUDE` のように名前と何個目かが出ます）．
  片方の成分がもう片方のノイズを表すことはないので、別々に選びます
- 選んだ結果は `ica_exclusion.json` に保存され、**2回目からは自動で再利用されて
  ウィンドウは開きません**（設定を変える必要はありません）
- **選び直したい**ときだけ `ica_exclusion` を **`gui`**（毎回、前回の選択が反映された
  状態で開く）にします．`False` にすると、ウィンドウも開かず除外もしません

**選んだ成分は既定では「除外」されません**（`ica_denoise` が `off`）．初期状態では
「どれがノイズか記録しておくだけ」で、ROI 信号や書き出す映像は**素の dF/F のまま**
です（MATLAB 版と同じ結果になります）．実際に**除外した信号を使いたい**ときは
`ica_denoise` を `subtract` にしてください．そのときだけ、ROI 信号・`dfWarped`・
動画・相関のすべてが「dF/F から除外成分を引いたもの」から計算され、出力ファイルに
「どの IC を除いたか」が一緒に記録されます．

### 5-7. ROI を自分で決める（Edit ROIs）

Stages の **「Edit ROIs」**（annotation が終わると押せるようになります）を押すと、標準脳の
上に ROI を並べたエディタが開きます．

- **「Add ROI (click atlas)」** を押してからアトラス上をクリックすると ROI が増えます．
  右の表で名前・位置（X, Y）・大きさ（Size）を直せます（反対半球に対称な ROI の追加、
  削除もできます）
- **「Overlay:」** で背景画像を切り替え、**「Show names」「Show borders」** で表示を調整できます
- **必ず「Save rois.csv」を押してください．** 押さないと何も保存されず、解析に反映されません
- **`rois.csv` を保存すると、以後の ROI 抽出・相関はアトラス既定の ROI ではなく
  この ROI を使います**（Log に `[roi] using N custom ROIs from rois.csv` と出ます）．
  元に戻したいときは **「Reset to atlas defaults」→「Save rois.csv」** を押すか、
  出力フォルダの `rois.csv` を削除します
- 保存すると、すでに `Done` だった roi / correlation は `Done (* param-changed)` になります．
  もう一度 **Run** してください

### 5-8. 終わったら

- **Figures** に各段の確認図が出ます（クリックで開閉）．
- 図をファイルとしても残したいときは、設定の **`save_figures`** を `png` などに
  してから実行します．
- どこまで進んだかは Stages の `Done` 表示で分かります．

## 第6章 結果はどこにできる？

既定では、入力フォルダの中に作られる **`asi`** フォルダの下にまとまります
（`<input_dir>/asi/<output_format>`．保存形式ごとに `asi/mat` や `asi/npy` などの
小部屋ができます）．Data の **`output_dir`** を指定した場合はそちらに出ます．

主なファイルの例：

| ファイル / フォルダ | 中身 |
| --- | --- |
| `reg_Ch{番号}.npy` | ゆれ補正後の各チャンネル映像 |
| `dff_{名前}.npy` | dF/F（明るさ変化）の映像 |
| `reg_meta.npz` | **前処理の完了印**（テンプレート・平均画像・フレーム数など）．GUI はこれを見て preprocess を `Done` と表示します |
| `hemovar_{名前}.npy` | 血流補正で説明できた分散の割合（R²）のマップ．`hemovar_qc` が on で、そのチャンネル名に `donner` がある場合に作られます |
| `{実験名}_dfWarped_{名前}_01.{拡張子}` | 脳地図に合わせた dF/F．拡張子は `output_format` に従います（`save_annotated_dF_mat` を on にしたとき） |
| `roiSignals_...` | 脳領域ごとの信号の時系列 |
| `rois.csv` | **Edit ROIs** で作ったカスタム ROI．**これがあると、ROI 抽出はアトラス既定ではなくこちらを使います**（元に戻すにはこのファイルを消すか、エディタの「Reset to atlas defaults」→「Save rois.csv」） |
| `corrMap/` | **Seed-based Corr. Maps** で計算した相関マップ（`.npy` と `.png`） |
| `map_for_annot/` | cpselect の背景に使う追加画像の置き場（`Add for Annot.` の出力もここ．自分で置いてもよい） |
| `marks.mat` | 脳地図合わせの対応点 |
| `ica_exclusion.json` | ノイズとして選んだ IC（チャンネル名ごと） |
| `ica/{名前}/basis.npz` | ICA の成分（次回そのまま再利用するため） |
| `ica/dff_{名前}.npy` | 除外 IC を引いた dF/F（`ica_denoise` を `subtract` にしたときだけ） |
| `db.yaml`, `ops.yaml` | このとき使った設定（あとで再現できる） |
| `pca_images/{名前}/`, `ica_images/{名前}/` | PCA / ICA の成分画像（チャンネル名ごと） |
| `fig_demux_qc.png`, `demux_means.npz` | チャンネル並び（demux）の自動チェック図とその元データ |
| `demux_correction.json` | Demux 補正ツールで作った補正（次回の前処理が自動反映） |
| `movies/` | 書き出した dF/F 動画（`save_movie` を on にしたとき） |
| `figures/` | 確認用の図（`save_figures` を on にしたとき） |
| `tiffs/` | チャンネルごとの TIFF（**5. TIFF output** の項目を on にしたとき） |

> 💡 **数値ファイルを MATLAB で使いたい**ときは `output_format` を `mat` にします．
> データがとても大きい（1つの配列で 4GB を超える）場合でも、自動的に MATLAB v7.3
> 形式で保存され、MATLAB の `load` でそのまま読めます（拡張子は `.mat` のまま）．

## 第7章 設定を保存する・呼び出す

毎回すべてを入れ直すのは大変なので、設定を保存・呼び出す仕組みがあります．
左の設定エリア上部のボタンを使います．

| ボタン | はたらき |
| --- | --- |
| **Load**（上部のパス欄と一緒に使う） | 保存済みの設定を読み込む．パス欄には `ops.yaml` / `db.yaml` そのもの、またはそれが入っているフォルダのどちらを入れてもかまいません．**`...` は「ファイルを選ぶ」ダイアログ**で `ops.yaml` / `db.yaml` を選びます（フォルダを選ぶボタンではありません．入力／出力フォルダを選ぶ `...` は **Data** セクションの中にあります）． |
| **Save** | 今の設定を、パス欄のフォルダに `db.yaml` / `ops.yaml` として保存． |
| **Load preset**（左のドロップダウンと一緒に使う） | 選んだプリセットに**書かれている処理設定だけ**を上書きします（入力/出力の設定＝db は今のまま）．**書かれていない項目は今の値が残ります**（初期値には戻りません）．同梱の `[std]` プリセットは新しい項目（`ica_denoise` / `demux_start_offset` / `channels_slip` / `hemovar_qc` など）を含まないので、**前の解析で入れた値が引き継がれます**．まっさらにしたいときは、いったん **(factory defaults)** を読んでから目的のプリセットを読んでください（`(factory defaults)` だけは全項目を初期値に戻します）． |
| **Save as preset** | 今の処理設定に名前を付けて自分用プリセットとして保存（`~/.asovi/presets/`）． |
| **Read last config** | **前回ソフトを閉じたときの処理設定**を呼び出す（`~/.asovi/last_ops.yaml` に終了時、自動保存されています）．入力/出力の設定は保持． |

ドロップダウンに並ぶプリセットは3種類です．

- **(factory defaults)** … 工場出荷の初期値に戻す
- **[std] …** … 同梱のプリセット（`src/asvimg/presets/`．例：2チャンネル用）．上書きはできません
- 名前だけのもの … あなたが **Save as preset** で保存したもの（`~/.asovi/presets/`）

> 📌 `~`（チルダ）は「あなたのユーザーフォルダ」を指す記号です．Windows なら
> `C:\Users\ユーザー名`、Mac なら `/Users/ユーザー名` のことです．自分用プリセットや
> 「前回の設定」は、この中の `.asovi` フォルダに保存されます．

**おすすめの使い方**：よく使う設定ができたら **Save as preset** で名前を付けて
保存しておき、次回は **Load preset** で呼び戻す．前回の続きをやるだけなら
**Read last config** が手軽です．

### 手で決めたことを残せば、2 回目以降は自動で流せる

このパイプラインで**人間にしか決められない**のは、次の 2 つです．

1. 脳地図合わせの対応点 → `marks.mat`
2. ノイズとして外す IC → `ica_exclusion.json`

この 2 ファイルは決めた瞬間に結果フォルダへ保存され、`annotation` と `ica_exclusion` は
初期値の **`cache`** のままでよいので、次からは**ウィンドウを一切開かずにこの 2 つの判断が
再生されます**（画面のないサーバーでも動きます）．ほかの設定を変えなければ同じ結果が出ます．

> ⚠️ **「人が決めたもの」はほかに 3 つあります．** いずれも前処理の `delete` では消えません．
> 結果を再現したいときは**上の 2 つと一緒に残してください**．
> - `rois.csv`（**Edit ROIs** が書きます）… **あるとアトラス既定の ROI の代わりに使われます**（消すと既定に戻り、ROI 信号と相関の数字が変わります）
> - `rois_source.csv`（`roi_space="source"` で使う ROI 定義）… **これを書くツールはありません．自分で用意するファイルです**
> - `demux_correction.json`（**Demux 補正ツール**が書きます）… `demux_start_offset` / `channels_slip` より**優先**されます

```bash
uv run python -m asvimg.run_pipeline --input-dir "<データのフォルダ>"
```

1 匹目を GUI で丁寧に見てから、残りをこのコマンドで一気に流す、という使い方が
できます．

## 第8章 NWB 形式で書き出す（データ共有・公開用）

解析が終わったデータを、**NWB（Neurodata Without Borders）** という神経科学の
共通ファイル形式にまとめられます。1 匹分の記録が 1 個の `.nwb` ファイルになり、
他の研究室や **DANDI**（公開アーカイブ）とそのまま共有できます。

これは**本体の GUI とは別の、独立した小さなツール**（`asovi-nwb`）です。本体で
解析を済ませてから使います。

> **なぜ別ツール？** NWB には、パイプラインが扱ってこなかった情報（動物の種・性別・
> 週齢・遺伝型、実験日時、実験者、指示薬や励起波長、1 画素の実寸…）が必要です。
> それらを入力する専用画面、という位置づけです。入力内容は
> `nwb_metadata.yaml` に保存され、次回は自動で戻ります（`marks.mat` などと同じ「人が
> 決めた情報」の仲間で、`delete` でも消えません）。

### 8-1. 起動する

解析済みの出力フォルダ（`…/asi/npy` のような、`reg_meta.npz` が入っているフォルダ）
を用意してから、ターミナルで：

```bash
uv run python -m asvimg.gui.nwb_editor
# 最初からフォルダを指定してもよい：
uv run python -m asvimg.gui.nwb_editor "D:\data\rec1\asi\npy"
```

別ウィンドウ「**NWB Builder**」が開きます。上部の **Browse** で解析済みフォルダを
選ぶ（または後から選び直す）と、fps・画像サイズ・グループ・そろっている成果物
（dF/F, ROI, warped, ICA）を自動で読み取って表示します。

### 8-2. 情報を入力する

上から順に埋めていきます。**★印は DANDI 公開に必須**です。

- **Session**：セッションの説明、日時（`2026-07-18T10:30:00+09:00` のような形式・タイムゾーン付き）、実験者、所属、キーワードなど
- **Subject（動物）**：★ `subject_id`（個体名）、★ `species`（`Mus musculus`）、★ `sex`（M/F/O/U）、★ `age`（`P90D`＝生後90日）または生年月日、遺伝型・系統
- **Device / Optical channels**：装置名、そしてグループごとに**励起波長・蛍光波長（nm）・指示薬**（例：GCaMP6s）。`pixel_size_um` は 1 画素の実寸（µm）
- **Payloads & options**：ファイルに何を入れるかのチェック（dF/F、ROI 信号、脳地図に合わせた dF/F、参照画像、ICA 成分、相関行列）。※生の蛍光画像は入れない構成です

### 8-3. 確認して書き出す

1. **Save metadata**：入力内容を `nwb_metadata.yaml` に保存（任意。Write 時にも自動保存されます）
2. **Validate**：必須項目の抜けをチェック。「valid — no DANDI-critical problems」なら OK
3. **Write NWB**：`<記録名>.nwb` を作成（進捗バーが動きます）
4. **Run nwbinspector**：公開できるかの自動チェック。**CRITICAL が 0** なら、この検査では致命的な問題が見つからなかった、という意味です。ほかのメッセージも読んでから提出してください（DANDI 用の設定が読めなかったときは黙って通常の検査に切り替わるので、0 でも DANDI が受け取る保証にはなりません）

> **うまくいかないとき**
> - 「atlas-warped dF/F」を選ぶには、脳地図合わせ（annotation）が済んで `marks.mat` が
>   あるフォルダが必要です。無い場合はそのペイロードだけ自動で飛ばし、ログに書きます。
> - 波長を空欄にすると蛍光波長が「不明（NaN）」になります。共有前に入れておきましょう。

## 第9章 困ったとき

### `uv` が見つからないと言われる

（例：`uv : 用語 uv が認識されません` / `command not found: uv`）

- **ターミナルを一度閉じて開き直しましたか？** インストール直後は反映されて
  いないことが多いです．開き直して `uv --version` を試してください．
- それでもダメなら、パソコンを再起動してからもう一度．

### `uv sync` が途中で止まる／遅い／失敗する

- 大きなファイルを落とすので**時間がかかります**．ネットにつながっていれば
  待てば進みます．
- 会社・大学のネットワークで弾かれることがあります．別回線（自宅など）で試すか、
  管理者に相談してください．
- 一度失敗しても、もう一度 `uv sync` を打てば続きから進むことが多いです．

### `python -m asvimg.gui` で「No module named ...」と出る

- **プロジェクトフォルダにいますか？** `pyproject.toml` があるフォルダに `cd`
  してから実行してください（第2章）．
- コマンドの綴りが合っているか確認（`asvimg.gui`）．

### GUI（画面）が出てこない

- リモート接続やサーバー上など、**画面のない環境では GUI は開けません**．画面の
  あるパソコンで実行してください．
- 起動に少し時間がかかることがあります．数十秒待ってみてください．

### **Run All** を押しても何も起きない（Log もステージ表示も動かない）

設定に矛盾があると、解析は**始まる前に止まります**．このときメッセージは Log ではなく、
**画面のいちばん上の1行**（ふだん `Idle.` と出ている場所）に `Invalid config: ...` として
表示されます．まずそこを読んでください．よくある内容：

- `channels_name` と `channels_prop` の**個数が違う**
- `ch_for_annotation` / `template_ch` / `demux_start_offset` が**チャンネル数以上**
  （0 から数えるので、2チャンネルなら `0` か `1` まで）
- `filter_xyt` が `x,y,t` の**3つの数字**になっていない
- `ica_denoise` を `subtract` にしたまま `skip_ica` をオンにしている
- `fps` が 0、`usfac` が 0

直してからもう一度 **Run All** を押します．

### 途中でエラー（State が赤い `Error` になる）

- 右下の **Log** に理由が出ています．最後のほうの行を読んでみてください．
- よくある原因：`channels_name` の並びが実際の撮影と合っていない／`input_dir`
  の指定間違い／空きディスク不足．
- チャンネル設定を直したら、**preprocess から**もう一度実行し直すのが安全です．

### `no ica/.../basis.npz — run the ICA stage first.` と出て止まる

（`ica_denoise` を `subtract` にしているときだけ起きます）

- **前処理（preprocess）をやり直すと、dF/F が作り直されるので、PCA / ICA の成分
  （`ica/`, `pca_images/`, `ica_images/`）はいったん消えます．** 除外 IC の記録
  （`ica_exclusion.json`）と脳地図の対応点（`marks.mat`）は残ります．
- そのため、preprocess のあとは **`ica` をもう一度 Run してから** roi / correlation /
  export を実行してください（**Run All** なら自動で正しい順に走ります）．
- `... is stale ...; Re-run the ICA stage.` も同じで、`ica` を実行し直せば直ります
  （古い成分の番号のまま「除外済み」と名乗るデータを作らないよう、わざと止めています）．

### チャンネルの並び（色）が途中でズレる／入れ替わる

- 前処理（preprocess）は **フレームの並び順だけ** で色（チャンネル）を割り当てて
  います．途中でフレームが1枚でも抜けると、そこから先の色が全部ズレることが
  あります．
- 前処理はこれを **自動でチェック** し、**Figures** に **「demux_qc」** という
  確認図を出します（画面なしで実行したときは `fig_demux_qc.png` として保存）．
  Log に `demux QC: WARNING ...` と出たら要注意です．
- ズレを直すには、専用の **Demux 補正ツール** を使います：

  ```bash
  uv run python -m asvimg.gui.demux_editor "<データのフォルダ>"
  ```

  > ⚠️ **フォルダの指定を省略しないでください．** 省略すると存在しない初期フォルダを
  > 見に行き、「No per-frame means found.」と出て何も表示されません．引数には
  > **撮影データのフォルダ**、または **`db.yaml` / `ops.yaml` の入った `asi/...`
  > フォルダ**を渡せます．先に preprocess を1回走らせておくと `demux_means.npz` が
  > できているので起動が速くなります（無い場合はその場で全フレームを読み直します）．

  ここで **全体の開始位相**（先頭の色の割り当て）や、**途中でズレた区間**（開始・終了
  フレーム）を指定して **Save** すると、`demux_correction.json` が作られ、**次回の前処理が
  それを自動で反映** します．**Analyze**（QC のやり直し）、**Suggest from slip**（検出された
  ズレから補正案を自動入力）、**Show / + edit here**（疑わしいフレームの前後を実画像で確認）、
  **Export corrected TIFF**（補正後のフレームを TIFF に書き出して確認）も使えます．
  補正が不要なら前処理の動作は変わりません．

### フォルダやファイル名に日本語・空白が入っている

- 基本は動きますが、うまくいかないときは**半角英数字だけの短い名前**のフォルダに
  データを置いて試すと切り分けやすいです．

### それでも解決しないとき

- **Log の最後の20行くらい**をコピーして、配布してくれた方や管理者に見せると
  早く解決します．「どのステージで」「どんなメッセージが」出たかが手がかりです．

## 付録A よく使うコマンド一覧

いつも **プロジェクトフォルダにいる状態** で使います（第2章の `cd`）．

| やりたいこと | コマンド |
| --- | --- |
| uv が入っているか確認 | `uv --version` |
| 初回セットアップ（部品をそろえる） | `uv sync` |
| GUI（本体画面）を起動 | `uv run python -m asvimg.gui` |
| 画面を使わず前処理だけ実行 | `uv run python -m asvimg.preprocess --input-dir "<データのフォルダ>"` |
| 画面を使わず全部を一気に実行 | `uv run python -m asvimg.run_pipeline --input-dir "<データのフォルダ>"` |
| チャンネルの並びのズレを直す（第9章） | `uv run python -m asvimg.gui.demux_editor "<データのフォルダ>"` |
| NWB 形式で書き出す（共有・公開用。第8章） | `uv run python -m asvimg.gui.nwb_editor "<解析済みフォルダ>"` |
| Andor の `.sifx` を1本の TIFF にまとめる | `uv run python -m asvimg.sifx_convert "<パス>"` |
| 前処理の細かいオプションを見る | `uv run python -m asvimg.preprocess --help` |

山括弧の中は、括弧ごと自分のパスに置き換えてください．**引用符は残してください** —
無いと、空白の入ったパスが2つの引数として読まれます．
